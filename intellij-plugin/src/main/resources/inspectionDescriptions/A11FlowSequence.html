Reports sequences of pipeline stages that cannot do what they look like they do.

collect, count and join each read a whole stream and yield exactly one value, so every stage after one of them is applied to a single value however long the stream was. That makes | count | drop 2 empty, | collect | count the number 1 whatever was collected, and | join "" | last 3 a stage with nothing to choose between. Also reported: | first 0, which never produces a value; the same reshaping twice in a row; and a counted skip n applied to something that is not a port or a node -- a status, a loop's value -- when what it drops is dropped for every reader of a stream and those have no such front. | drop n is the one that drops values from a pipeline of one reader's own.

The stages that reshape each value -- map, where, truncate, text, json, packb -- are not reported after a reducing stage: mapping the one value a collect produced is how a flow builds a prompt out of many pages.
