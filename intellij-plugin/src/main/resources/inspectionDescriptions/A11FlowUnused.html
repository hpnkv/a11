Reports statuses, waits and declarations nothing in the flow uses.

The one worth having: a step written try, whose status nothing reads. try says a call may fail without ending the flow, and wait / status is how the flow finds out that it did -- so a try nobody asks about turns a failure into ports that are silently empty. Either ask, or let the call fail.

Alongside it: a barrier bound to a name nothing reads (the flow still waits there, so the name is the dead part -- the fix removes it and leaves the wait); an out port nothing writes, which a caller reading it gets nothing from; a header declared under an alias nothing uses; a nodes map nothing is placed in; and a for variable no pass of the loop reads.

An in port nothing reads is deliberately not reported: a flow's ports are its public interface, and one it accepts and ignores is a choice about that interface rather than a mistake.
